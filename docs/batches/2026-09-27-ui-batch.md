## Findings

### B1
- Cause: `battle_card_view._forecast_hero_phase` was a hand-written model that
  deliberately skipped mark, execute, chain, breach, detonate and relic
  multipliers (TRUTH recorded it as a "safety property"), and the enemy card
  added only raw `dmg`. The hero readout's Detonate number came from a
  separate burst helper, so the two disagreed.
- Fix: `resolve_round`'s preamble and hero loop are now one function,
  `_resolve_hero_phase`. `forecast_hero_phase` runs it on deep copies of the
  unit states with `_forecast_only` set (skips `SaveManager.record_nat20`,
  `record_hero_death`, `GameState.grant_battle_start_consumables`,
  `dead_mans_hand_used`) and saves/restores the roll-provider streams. Enemy
  cards read HP lost, shield left and death from the copies; the burn tick is
  read after the hero phase; the Detonate readout reads the burst that lands.
- Class check (all now exact through the same run, each has a gate case):
  detonate finite / permanent / lethal, the burn tick after a detonate, a
  burn tick with no hit, execute, chain, mark, breach, pierce, spike
  retaliation (hero card), a relic damage multiplier and an Overload Loop
  echo. Pre-fix code fails 11 of the 12 cases (the plain burn tick was
  already right).
- Not in scope, listed in TASK_QUEUE: the ENEMY phase is still a raw
  telegraph (enemy riders on heroes, and an enemy shield cast in the enemy
  phase that will absorb the end-of-round burn tick).
- Test change: the leech case now wounds the leecher first. The old model
  showed an uncapped heal on a full-HP hero; the real heal there is 0.
- Captures: `debug_artifacts/ui_batch_2026-09-27/B1/` (before/after/compare,
  both sizes). Before: Scrap shows 12 damage plus a 3 burn tick. After: 21
  (12 + detonate 9) and no tick, which is what resolves.

### B2
- Cause: the live Detonate value was built as `"%s %d"` ("DT 9"). EffectPip
  drops the keyword letters for icon kinds and kept the space, so the number
  sat one space glyph (25 px readout, 15 px card) further from its icon.
- Fix: the value is built as "DT9" (the SP3 / SI2 shape), and
  `EffectPip._numeric_suffix` trims whitespace, so the class can't come back.
- Class check: every icon + number pair built by `EffectPip.build_group`
  (all hero and enemy abilities in live data, the live Detonate value, and two
  deliberately spaced values) is laid out in both pip profiles and measured
  glyph to icon (hero base kits, all 16 evolution kits, enemies). All equal
  `icon_value_gap`. Detonate was the only value authored with a space. Status
  chips use their own builder with integer values and a fixed 1 px
  separation (no whitespace path).
- Gate: `pip spacing` (`scripts/debug/pip_spacing_test.gd`), in verify_gate.
  Old code: 29 px vs 4 px (readout), 19 px vs 4 px (card).
- Captures: `debug_artifacts/ui_batch_2026-09-27/B2/` (both sizes, plus
  `zoom.png`).

### B3
- Cause: `_refresh_encounter` hid the site line on a locked encounter and
  toggled the status line's visibility, and the banner's text column is
  vertically centred, so the name, threat row and LOCKED moved.
  `_show_operation_detail` set the detail box to alpha 0 when locked (G-16).
- Fix: every slot is fixed: subtitle (one 52 px line, clipped), status line
  (always present), lore slot (static: shown only if any operation has lore,
  none do), detail box (3 story lines + THREATS row). Locked: subtitle shows
  "Clear <previous operation> to unlock" (new `SaveManager.operation_unlocked_by`)
  at the 48 px text floor, because at 52 px it is 511 px against a 486 px
  column. The hero dossier is gone from the detail box; long-press on a tile
  opens the unit popup with its blurb added (`unit_inspect_payload`).
- Class check: every element of the screen (banner, name, subtitle, status,
  lore, dots, detail box, story, THREATS row, all 8 tiles, DEPLOY) is compared
  rect by rect across all five encounters (twice round) and across a squad
  toggle; nothing moves. The unlocked Facility banner now also keeps an empty
  status row (it had none before), so its text sits 2 px higher than before.
- Supersedes G-16's transparent locked dossier (recorded in
  DECISIONS_RESOLVED and TRUTH).
- Tooling: `home_screen_capture.gd` no longer compiled under `-s` (bare
  `HelpMenu` reference); fixed, and it takes `--capture-window=WxH`.
- Captures: `debug_artifacts/ui_batch_2026-09-27/B3/` (encounter 1, locked
  encounter 2, after a tap, long-press popup; both sizes).
