## Diagnosis (why faces 1-7 were short)
Measured on 3,000 hops before the fix:
- **Start vs landed face:** the die landed on its own starting face **19.1%** of the time (fair d20: 5%, z=35). Every start group (1-5, 6-10, 11-15, 16-20) was non-uniform (chi-square 61-325 vs 50.8 critical).
- **Rotations / bounces:** mean **0.95 turns** per hop (0.24-2.33) and about **28 floor bounces** before rest (max 42).
- **Why so little tumble:** in the gate's slot the hop is cut short by the leaning tray walls (the die is stopped about 0.45 up). Jolt also clamps angular velocity near 30 rad/s, so raising the spin constants changed nothing (turns 1.07 at spin 90-150).

## Fix
`DiceTray3D._hop_die` now launches the die from a uniformly random orientation (random quaternion), lifted so its lowest corner clears the floor by 0.02, then applies the same upward impulse and spin. Horizontal movement is still locked, so slot travel stays 0 and neighbours are untouched. Physics still decides the face. One-frame orientation pop at launch is the cost (same frame as the G-27 reprint).

After: 10,000 hops chi-square 14.5 (critical 50.8), own-face 4.97%, start groups 14.9 / 10.7 / 12.5 / 19.2. Turns and bounces are unchanged (about 0.97 and 28.7); the randomness comes from the launch pose.

## Gate (`scripts/checks/reroll_hop_gate.py`, `scripts/debug/reroll_hop_gate.gd`)
- 10,000 hops, sharded over 8 Godot processes and pooled through `--analyze` (one copy of the statistics, in the .gd). About 185 s on this machine; budget 300.
- Tests: pooled chi-square, per-start-group chi-square (each group needs 500+ hops), own-starting-face z-test, plus the old contact / slot / snap rules. Critical values are p 0.0001 (chi-square 50.80) and z 4.42 so ten-in-ten is not a coin flip.
- Deliberate breaks, each must fail: `uniform`, `start` (launch randomization removed), `contact`, `slot`, `snap`. All five detected every run.
- Fixed a stall: leg output now goes to temp files (an unread pipe filled and stalled shards; first run took 24 min instead of 3).
- A stale `.godot` class cache made every headless run print `StateCode` script errors and left autoloads (DiceAudio) unloaded, so physics contact monitoring was off in the earlier gate runs. `godot --headless --import` fixes it; with autoloads loaded the contact rule still holds (0 neighbour contacts, 0 slot travel, 0 snap changes).
