cancelled the armed Nudge. Item 7 fixed that bug (`ProtocolActions.claim_die_taps`), so the

7. **64x64 headless window (gate audit not done):** headless Godot runs at a 64x64 window, so
   window-scaled values are distorted in every headless gate. Found while building `touch scroll`:
   the long-press drag tolerance (26 device px) becomes ~975 design px, so no drag ever cancels a
   tap. `touch_scroll_test.gd` sets `root.size = 540x1200` to avoid it. Other headless gates were
   **not** audited for the same blind spot; any gate that relies on drag tolerance, real pointer
   hit-testing or physical-pixel sizes may pass for the wrong reason. `reward_model_test.gd`
   already notes headless `push_input` hit-testing as unreliable.

   **Audited 2026-10-02 (report only; the fix is deferred, Kev).** Measured: headless root is
   64x64, so the expand stretch lays the game out on a **2400x2400** canvas at scale 0.0267
   (`--resolution` is ignored headless; only `root.size` in the script works). A/B run of the
   43 headless Godot gates that set no window of their own, at 64x64 and at 1080x2400 (Linux
   Godot 4.6.2): **identical verdicts, no false pass found today.** The two differences on the
   first pass (`tutorial smoke`, `battle checkpoint`) were CPU contention; each passes alone at
   1080x2400. The protection is accidental, not structural:
